# fineapi-qqbot（星芽 QQ 助手）

AstrBot 插件：在 QQ 群/私聊绑定星芽（`xingya.site`）账号、查询余额、首次绑定赠送额度。

> 当前版本：**0.4.4**（MVP + 模型状态图片 + 芽点抽奖 @ 中奖者 + 老用户注册礼静默过滤）。适配 QQ 官方机器人、QQ 官方 Webhook 和 OneBot v11（aiocqhttp）。

## 功能

| 命令 | 权限 | 说明 |
|---|---|---|
| `/绑定 <用户名> <ID>` | 用户 | 用户名在前、ID 在后；两个参数都匹配才绑定成功 |
| `/解绑` | 用户 | 只解除本地绑定，不影响站点账号 |
| `/余额` | 用户 | 余额 / 累计消耗 / 调用次数 |
| `/领取首绑礼` | 用户 | 领取首次绑定赠送（失败可重试） |
| `/抽奖` | 用户 | 参与当前会话的抽奖 |
| `/抽奖信息` | 用户 | 查看当前抽奖 / 最近开奖结果 |
| `/<模型>状态` | 用户 | 模糊查询模型近 1 小时状态，例：`/claude状态` |
| `/模型状态` | 用户 | 全部模型近 1 小时调用量 Top 10 |
| `/我的ID` | 用户 | 查看平台用户 ID / 群 ID（配置用） |
| `/用户命令` | 用户 | 只显示用户命令 |
| `/管理命令` | 管理员 | 只显示管理命令 |
| `/芽点帮助` | 用户 | 完整帮助；管理部分仅管理员可见 |
| `/强制解绑 <平台用户ID>` | 管理员 | 删除某个平台用户的绑定 |
| `/绑定查询 <平台用户ID或星芽ID>` | 管理员 | 查看绑定与礼物状态 |
| `/补发首绑礼 <平台用户ID> [force]` | 管理员 | 人工补发；异常状态需加 `force` |
| `/发抽奖 [时间] [芽点] [人数] [标题]` | 管理员 | 创建抽奖；不填用配置默认值 |
| `/开奖 [编号]` | 管理员 | 立即开奖；不填开当前会话的抽奖 |
| `/取消抽奖 [编号]` | 管理员 | 取消未开奖的抽奖 |
| `/抽奖管理` | 管理员 | 查看最近的抽奖记录 |
| `/补发抽奖 [编号]` | 管理员 | 补发未到账的中奖芽点 |

> **平台用户 ID**：QQ 官方机器人给的是 OpenID（不是 QQ 号），同一用户在不同群/私聊
> 可能得到不同 OpenID。插件按平台 ID 做绑定唯一性；管理命令请使用 `/绑定查询 <星芽ID>`
> 先查到对应的平台用户 ID。
>
> 管理员识别建议：把管理员**私聊机器人**时的 C2C OpenID 填到 `access.admin_qqs`，
> 或在 AstrBot 中把该 OpenID 配为管理员。群内 OpenID 与私聊 OpenID 可能不同，
> 只填群内 ID 可能导致换个群就失去管理权限。
>
> 如果使用 OneBot/aiocqhttp，平台用户 ID 就是 QQ 号，配置方式不变。
> 可以用 `/我的ID` 直接查看当前会话的平台用户 ID 和群 ID。

- 首绑礼默认 **$1**（后台可调），发到**普通余额**；`$1 = 100 芽点 = 500000 quota`。
- 只有 **Star 用户 ID 大于 `gift.new_user_id_after`（默认 8352）** 的新用户才发放；
  ID ≤ 阈值视为老用户，`/绑定` 和 `/领取首绑礼` 都不会发放。
- **老用户不显示首绑礼提示**（内部仍标记 `skipped`，管理员可查）；
  新用户会提示实际发放金额，例如 `$1.0000（100.00 芽点）`。
- 管理员可用 `/补发首绑礼 <平台用户ID> force` 人工覆盖。
- 模型状态：统计近 1 小时模型调用，**排除 400-499 客户端错误**，
  同一用户的重复错误只算 1 次，按“成功调用 / 去重后调用数”计算正确率；
  少于 5 次显示“数据不足”。
- 不保存用户密码、令牌或聊天内容。
- 签到暂未实现。

### 绑定格式

```text
/绑定 <用户名> <ID>
/绑定 alice 123
```

- **用户名在前，ID 在后**；
- ID 必须是纯数字；
- 用户名区分大小写，必须与站点账号完全一致；
- 兼容旧的“ID 在前”写法，但会提示新格式，建议统一使用新格式。

## 安装

### 方式一：AstrBot 从仓库 URL 安装（推荐）

AstrBot WebUI → 插件 → 从仓库 URL 安装：

```text
https://github.com/flowleaves/astrbot_plugin_fineapi_qqbot
```

安装后重载插件即可。AstrBot 会自动把仓库克隆到：

```text
AstrBot/data/plugins/astrbot_plugin_fineapi_qqbot/
```

### 方式二：手动克隆

```bash
cd AstrBot/data/plugins
git clone https://github.com/flowleaves/astrbot_plugin_fineapi_qqbot.git
```

然后安装依赖（AstrBot 通常已自带 `aiohttp`）：

```bash
pip install -r astrbot_plugin_fineapi_qqbot/requirements.txt
```

最后在 AstrBot WebUI → 插件 页面重载插件。

> 仓库根目录就是插件目录，包含 `main.py`、`metadata.yaml`、`_conf_schema.json`，
> 不要再套一层子目录。

## 配置

在插件配置页填写：

| 配置项 | 说明 |
|---|---|
| `site.base_url` | 站点地址，默认 `https://xingya.site`，不要以 `/` 结尾 |
| `site.access_token` | 管理员个人访问令牌（PAT） |
| `site.admin_user_id` | rc50 填 `0`；旧版 NewAPI 填管理员用户 ID |
| `site.max_concurrent_requests` | 同时请求星芽站点的最大并发，默认 `12` |
| `gift.enabled` | 是否开启首绑礼 |
| `gift.amount_usd` | 赠送金额，默认 `1.0` |
| `gift.new_user_id_after` | 新用户起始 ID，默认 `8352`；`ID > 该值` 才发放 |
| `lottery.winner_display` | 开奖名单显示：`at`（默认，@QQ）或 `id`（星芽用户 ID） |
| `binding.allow_group` / `allow_private` | 允许群聊/私聊绑定 |
| `access.whitelist_groups` | 群白名单（官方机器人为 `group_openid`），留空表示所有群 |
| `access.admin_qqs` | 额外插件管理员平台用户 ID（官方机器人为 OpenID，不是 QQ 号） |

### 创建访问令牌

1. 用管理员账号登录星芽站点；
2. 进入个人设置 → 安全 → 访问令牌；
3. 新建令牌，至少勾选：

   - `user:read`（查询用户）
   - `user:write`（发放首绑礼）
   - `log:read`（模型状态监控；不开启该命令可不给）

4. 复制令牌填入 `site.access_token`。

> 令牌只会用于 `GET /api/user/:id`、`POST /api/user/manage`、
> `GET /api/log/`（模型状态）和 `GET /api/pricing`（模型名候选），
> 不会用于登录用户账号。

### 模型状态说明

- 命令：`/<模型>状态`，支持模糊匹配，例如 `/claude状态`、`/gpt状态`；
- AstrBot 会先去掉唤醒前缀 `/` 再交给插件，所以 `claude状态`、`gpt状态` 同样可用；
- `/模型状态`：全部模型近 1 小时调用量 Top 10；
- 数据源：`GET /api/log/?type=2`（成功调用）+ `type=5`（错误），默认近 60 分钟；
- 排除 `400-499` 客户端错误；
- 同一用户在同一模型上的重复错误只算 **1 次**；
- 调用数 = 成功调用 + 去重后的错误数；正确率 = 成功调用 ÷ 调用数；
- 少于 **5 次**调用显示“数据不足”；
- 模糊匹配多个模型时按调用量降序显示前 **10** 个；
- 默认输出文转图图片；文转图失败自动回退 Markdown 文本；
- 成功日志、错误日志、模型价格表**并发拉取**，总耗时受 `model_status.max_fetch_seconds` 限制（默认 12 秒）；
- 需要 PAT 具备 `log:read`，并建议站点开启 `ERROR_LOG_ENABLED=true`；
- 结果缓存默认 60 秒。

> 如果日志里出现 `t2i.network_strategy: Endpoint https://t2i.soulter.top/text2img failed: HTTP 500`，
> 这是 AstrBot 默认的公共文转图服务不可用，AstrBot 会自动尝试下一个渲染端点；
> 不是插件报错。可在 AstrBot「配置 → 文转图」里调整或移除失效端点。

#### 文转图模板

把仓库里的 `templates/model_status.html` 全文粘贴到：

```text
AstrBot WebUI → 配置 → 文转图 → 自定义 HTML 模板
```

模板只使用 AstrBot 允许的 `text` / `version` 变量，不会触发
“Unauthorized Jinja2 variable”校验。未配置时插件仍能工作（默认文转图或文本回退）。

## 抽奖

奖品是**芽点**，开奖后发到中奖者绑定的星芽账号普通余额。参与者必须先 `/绑定`。

> **抽奖按会话隔离**：私聊创建的抽奖只能在私聊参与，群内创建的抽奖只能在该群参与；
> 同一个会话同时只能有一场进行中的抽奖。如果要让某个群参与，请直接在目标群发 `/发抽奖`。

### 管理员创建

```text
/发抽奖                          # 默认：30 分钟后开奖，100 芽点，1 人
/发抽奖 100                      # 100 芽点，30 分钟后，1 人
/发抽奖 100 3                    # 100 芽点，3 人，30 分钟后
/发抽奖 21:30 100 1 今晚福利      # 今晚 21:30 开奖
/发抽奖 2026-11-10T21:30 100 3 周末福利
/发抽奖 2h 50 2 下午茶            # 2 小时后开奖
```

- 时间格式：`30m` / `2h` / `1d`、`21:30`、`今天 21:30`、`明天 21:30`、
  `11-10T21:30`、`2026-11-10T21:30`；
- 奖品按中奖人数平均拆分，余数分给前面的中奖者；
- 每人至少 1 芽点，单次上限、人数上限可在配置里限制；
- 每个会话同时只能有一个进行中的抽奖。

### 开奖

- 到点后后台任务每 15 秒检查一次并自动开奖；
- 机器人掉线期间到点的抽奖，重启后会补开；
- 结果会主动发送到创建抽奖的会话；
- 中奖名单默认 **@ 绑定的 QQ**，隐藏星芽用户名；私聊、官方机器人或 @ 失败时自动回退 `用户 #星芽ID`；
- 如果平台限制主动消息发送失败，用户可发 `/抽奖信息` 查看最近结果；
- 奖励发放失败时管理员可用 `/补发抽奖 <编号>` 重试。

> 抽奖仅使用虚拟芽点，不涉及真实货币或现金兑换。

### 并发与性能

发布抽奖后短时间内集中 `/绑定`、`/抽奖` 时：

- 插件→星芽站点的请求受 `site.max_concurrent_requests` 限制（默认 12），
  避免瞬间打满上游触发 429；
- 开奖时用一次 SQL JOIN 取出仍符合资格的参与者，不再逐个查绑定；
- 开奖发奖并发执行，100 人中奖不会因为逐个发放拖成几十秒；
- SQLite 使用 WAL + `synchronous=NORMAL`，集中写入时不会每次提交都等待磁盘同步；
- 本地实测：500 次并发参与约 80 ms，500 次并发绑定约 90 ms，
  真正的瓶颈通常在上游 NewAPI 的 HTTP 请求。

## 数据

- 数据目录：`AstrBot/data/plugin_data/astrbot_plugin_fineapi_qqbot/fineapi.db`
- 表：`bindings`（平台用户 ↔ 星芽用户）、`op_log`（绑定/解绑记录）、
  `gift_grants`（发放台账，解绑/重绑后仍然保留）、
  `lotteries` / `lottery_entries` / `lottery_winners`（抽奖、参与、中奖发放记录）
- 首次发放前写入 `pending`，成功后 `granted`；失败为 `failed`；
  老用户不发放时标记 `skipped`；请求超时等无法确认结果时标记 `unknown`，需要管理员核对后
  `/补发首绑礼 <平台用户ID> force`。
- `gift_grants` 对平台用户 ID 和星芽用户 ID 都做了唯一约束：
  **解绑再绑、换号重绑都不会重复发放首绑礼**。

## 已知限制

- 使用 QQ 官方机器人，无法获取 QQ 等级/入群时长，因此**不做首绑礼风控门槛**（按产品决定取消）。
- 官方机器人只能被动回复，主动私聊能力受平台限制。
- 模型状态依赖 PAT 的 `log:read`；建议站点开启 `ERROR_LOG_ENABLED=true`，
  否则错误日志为空，正确率可能偏高，图片标题会提示确认该变量。
- 成功/错误日志默认各最多分析最新 1000 条（`model_status.max_pages` 可调），
  调用量很大时正确率为样本统计；总拉取时间超过 `model_status.max_fetch_seconds`
  时使用已拉到的数据继续统计，避免命令长时间无响应。
- 站点若开启 Cloudflare WAF，请确保机器人出口 IP 不被拦截。
